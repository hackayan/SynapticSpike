# Pipeline Explanation & Instructions

## High-Level Overview

This repository contains an electroencephalography (EEG) analysis pipeline designed to investigate the neural correlates of predictive coding during a "Roving Mismatch Negativity" (MMN) paradigm. The pipeline works by mapping trial-by-trial prediction errors—estimated computationally using a Hierarchical Gaussian Filter (HGF)—to the amplitude of single-trial EEG responses.

The analysis flows through the following stages:
1. **Preparation:** Standardizing computational modeling outputs (HGF).
2. **Extraction:** Pulling single-trial amplitudes from specific electrodes (Fz, Cz, Pz) from preprocessed `.set` EEG files and matching them with HGF data.
3. **Merging:** Combining data from all participants into a single large dataset.
4. **Statistical Modeling:** Running regressions (Linear Models vs. Linear Mixed-Effects Models) at every millisecond to identify when neural activity correlates with prediction errors, using cluster permutation tests to correct for multiple comparisons.
5. **Behavioral Correlation:** Correlating the EEG-derived measures with self-reported schizotypy scores (O-LIFE).

## Detailed Breakdown of Scripts

### Python Scripts (Data Preparation & Extraction)

**1. `python/01_prep_hgf_output.py`**
- **Purpose:** Formats the output generated by the `pyhgf` library for downstream analysis.
- **Details:**
  - Loads the HGF output (`trialwise_predictions.csv`) and behavioral trial sequence data (`behavioral_data_trialwise.csv`).
  - Renames columns (e.g., `epsilon_2` to `eps2`, `trial_type_binary` to `u`) to match expected names in the R scripts.
  - Merges categorical trial codes (`cat_code`) into the dataframe.
  - Drops unnecessary columns (like `Response_Time`) and performs sanity checks (e.g., ensuring exactly 1392 trials exist and `eps2` values match expected deviations).
  - Saves the cleaned dataset as `hgf_output.csv`.

**2. `python/02_extract_all_subjects.py`**
- **Purpose:** Extracts single-trial EEG amplitude data and merges it with behavioral and modeling data.
- **Details:**
  - Reads preprocessed `.set` EEGLAB files for each subject.
  - Pulls out amplitude data for specific target channels (`Fz`, `Cz`, `Pz`) across all timepoints and trials.
  - Converts this 3D matrix (channels × time × trials) into a long-format DataFrame.
  - Merges the EEG data with the trial-level HGF data (`hgf_output.csv`) and subject-level survey data (`Survey_scores.csv`).
  - Saves a separate `.csv` file for each subject.
  - Concatenates all individual subject files into one massive file: `merged_eeg_hgf_ALL.csv`.
  - *(Note: A SLURM script `01_extract_eeg_array.sh` exists to parallelize this process by running one Python instance per subject).*

### Bash Scripts (SLURM Job Submission)

**1. `slurm/01_extract_eeg_array.sh`**
- **Purpose:** Submits an array job on the HPC. Each job extracts EEG data for a single subject using Python, speeding up extraction significantly.

**2. `slurm/02_concat_subjects.sh`**
- **Purpose:** After the array job finishes, this script runs a brief Python snippet to concatenate all the individual `merged_S*.csv` files into the final `merged_eeg_hgf_ALL.csv`.

**3. `slurm/03_submit_analysis.sh`**
- **Purpose:** Submits an array job with 3 tasks to run the statistical analysis (`03_lm_vs_lmer_analysis.R`) independently and in parallel for the three channels (Fz, Cz, Pz).

**4. `slurm/04_olife.sh`**
- **Purpose:** Submits a job to run the final behavioral correlation script (`04_olife_correlation.R`).

### R Scripts (Statistical Analysis)

**1. `R/03_lm_vs_lmer_analysis.R`**
- **Purpose:** Performs timewise regression to find when prediction errors modulate EEG amplitude.
- **Details & Statistical Models:**
  - **Data Cleaning:** Removes subjects with >30% bad epochs. Orthogonalizes `eps3` (volatility prediction error) with respect to `eps2` (sensory prediction error) to isolate their unique contributions. Both predictors are z-scored.
  - **Timewise Regression:** At every single time point (e.g., from -100ms to 400ms), it fits two models predicting EEG amplitude:
    - **Linear Model (LM):** `amplitude ~ u + Condition + eps2_z + eps3_orth_z`. Assumes all trials are independent.
    - **Linear Mixed-Effects Model (LMER):** `amplitude ~ u + Condition + eps2_z + eps3_orth_z + (1|subject)`. Adds a random intercept for subjects, accounting for the fact that trials within the same subject are correlated.
  - **Cluster Permutation Test:** To correct for multiple comparisons across time, the script finds contiguous time points where the t-value exceeds a threshold (2.0), summing these into a "cluster mass". It then permutes (shuffles) the prediction error values 500 times, recalculating the max cluster mass each time to build a null distribution. Real clusters larger than the 95th percentile of the null are considered significant.
  - *(Note: The code was corrected during this review to permute values at the trial level rather than completely randomly, which preserves temporal autocorrelation and valid null distributions).*
  - **Output:** Generates plots comparing LM and LMER t-values over time for both `eps2` and `eps3`.

**2. `R/04_olife_correlation.R`**
- **Purpose:** Investigates whether the strength of neural predictive coding relates to schizotypy traits.
- **Details & Statistical Models:**
  - Calculates two subject-level metrics in the 100-200ms window:
    1. **MMN Amplitude:** Average amplitude of deviant trials minus standard trials.
    2. **eps2-EEG Coupling:** The within-subject Pearson correlation between single-trial `eps2` values and single-trial EEG amplitudes.
  - Calculates the Pearson correlation between these metrics and the `Total_O_LIFE_Score`.
  - Generates scatter plots with regression lines and a grand average ERP waveform plot.

## Code Review & Assessment of Completeness

**Structural Integrity:** The repository structure was initially inconsistent (`scripts/` vs `R/`). This has been fixed. The pipeline is now logically separated into `python/`, `R/`, and `slurm/`.

**Statistical Validity:**
- A significant flaw existed in the original cluster permutation test (`03_lm_vs_lmer_analysis.R`). Shuffling a long-format dataframe containing both channels, trials, and timepoints completely randomly breaks the fundamental structure of the data. Shuffling must occur at the level of the *trial* to preserve the temporal autocorrelation of the EEG signal within a trial. **This has been fixed.**
- The orthogonalization of `eps3` with respect to `eps2` using `resid(lm(eps3 ~ eps2))` is a standard and robust way to ensure the volatility regressor explains *unique* variance not already captured by the sensory regressor.
- Using `(1|subject)` in LMER is appropriate, though an even more stringent model might include random slopes `(1 + eps2_z | subject)` if computation time permits. Given the pipeline is set up for HPC, this is acceptable.

**Missing Elements / Completeness:**
- **Pre-computed HGF data:** The pipeline assumes you already have `trialwise_predictions.csv` from running `pyhgf`. The code to actually fit the HGF model to the sequence is not in this repository.
- **EEG Preprocessing:** The pipeline assumes EEGs are already preprocessed, epoched, and saved as `.set` files.
- **Multiple Comparisons across Channels:** The permutation test corrects for multiple comparisons *across time* within a channel. It does not correct across the 3 channels (Fz, Cz, Pz). Depending on strictness, a Bonferroni correction (alpha = 0.05 / 3) might be considered when interpreting final p-values.

## Instructions: Running on IITK Param Sanganak HPC

Given your data (`.set` files, `trialwise_predictions.csv`, `behavioral_data_trialwise.csv`, `Survey_scores.csv`), here is exactly how to run the pipeline.

### Step 1: Set up the Directory
Log into the HPC and ensure your directory structure in your home folder looks exactly like this:
```text
~/rmmn/
├── raw_set/
│   ├── sS01_sequence_epochs.set
│   ├── sS02_sequence_epochs.set
│   └── ... (all your .set files)
├── trialwise_predictions.csv
├── behavioral_data_trialwise.csv
├── Survey_scores.csv
├── python/
│   ├── 01_prep_hgf_output.py
│   └── 02_extract_all_subjects.py
├── R/
│   ├── 03_lm_vs_lmer_analysis.R
│   └── 04_olife_correlation.R
└── slurm/
    ├── 01_extract_eeg_array.sh
    ├── 02_concat_subjects.sh
    ├── 03_submit_analysis.sh
    └── 04_olife.sh
```

### Step 2: Install R Dependencies (One-time setup)
If you haven't already, request an interactive session and install the necessary R packages via conda/CRAN as mentioned in the README:
```bash
conda install -c conda-forge r-lme4 r-future r-future.apply -y
Rscript -e "install.packages(c('dplyr','readr','ggplot2','tidyr','patchwork'), repos='https://cloud.r-project.org')"
```

### Step 3: Run the Pipeline via SLURM
Navigate to your working directory:
```bash
cd ~/rmmn
```

**1. Prepare HGF data (Runs locally on login node, takes < 5 seconds):**
```bash
python3 python/01_prep_hgf_output.py
```
*Wait for this to finish before proceeding.*

**2. Extract EEG Data:**
You need to adjust the array size in `slurm/01_extract_eeg_array.sh` to match the number of your `.set` files. For example, if you have 33 files, edit the file to say `#SBATCH --array=0-32`. Then submit:
```bash
sbatch slurm/01_extract_eeg_array.sh
```
*Wait for all jobs in the array to complete (`squeue -u <your_username>`).*

**3. Concatenate Data:**
```bash
sbatch slurm/02_concat_subjects.sh
```
*Wait for this to complete.*

**4. Run Statistical Analysis:**
```bash
export WORK_DIR=$HOME/rmmn
export N_PERM=500
sbatch slurm/03_submit_analysis.sh
```
*This will spawn 3 jobs (for Fz, Cz, Pz). Wait for all to complete. This is the longest step.*

**5. Run Behavioral Correlation:**
```bash
sbatch slurm/04_olife.sh
```

### Step 4: View Results
Your results will be saved in `~/rmmn/results/`. You can copy this folder back to your local machine using `scp` or `rsync` to view the generated plots and `.rds` data objects.
